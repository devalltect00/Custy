### 🧰 Repository metadata maintenance

- Add `scripts/repository/src/sync_metadata.py` as a source-checkout helper,
  separate from the installed CLI, release pipelines, and package publication.
- Read the shared repository description from `[project].description` and
  provider-specific topics from `[tool.devalltect.github].topics` and
  `[tool.devalltect.gitlab].topics` in the root `pyproject.toml`.
- Resolve one GitHub and one GitLab repository from ordered Git remote
  candidates; use the first eligible fetch URL rather than broadcasting to
  every remote or deriving repository targets from package metadata.
- Use authenticated `gh` and `glab` only for an explicitly requested live run.
  Keep `--dry-run` limited to local metadata inspection and read-only Git
  discovery, without provider API requests.
- Document that topic synchronization replaces existing lists, that empty or
  missing lists clear topics, and that a live run has no confirmation prompt
  or cross-provider rollback.
